# 24. GIT AND DEPLOYMENT

Use Git and GitHub.

Recommended branches:

- main
- develop
- feature/*
- fix/*

Example:

- feature/product-database
- feature/comparison-engine
- feature/product-viewer
- fix/mobile-navigation

Repository should contain:

- Custom theme
- coc-core plugin
- Documentation
- Deployment instructions
- Testing instructions
- Configuration examples

Do not commit:

- wp-config.php secrets
- uploads
- private database dumps
- cache
- credentials

Deployment must only update controlled application files.

Never overwrite:

- WordPress core
- wp-config.php
- uploads
- Production database
- Unrelated plugins
- Existing user content

Create a staging deployment procedure.

Create backup and rollback instructions.

Document the exact files that must be uploaded to production.

# 29. FINAL INSTRUCTIONS TO CODEX

Think like a senior engineer and product designer.

Do not optimize for writing the most code. Optimize for a high-quality, maintainable, reliable product.

Do not produce a generic template website.

Do not use fake data as real product information.

Do not use placeholder buttons that do nothing.

Do not leave dead links or non-functional interactions.

Do not generate empty sections merely to make the website look complete.

Do not sacrifice accessibility for animation.

Do not sacrifice SEO for client-side rendering.

Do not sacrifice performance for 3D effects.

Do not introduce Node.js, TypeScript, React, or a production build pipeline.

Do not deploy untested code.

Do not claim completion without evidence.

When a requirement is unclear, document the assumption and ask for a decision when it affects business logic, data accuracy, branding, or production configuration.

**The final goal is a premium, visually distinctive, 3D-enhanced, highly usable portable oxygen concentrator research and comparison platform that runs directly on standard PHP WordPress hosting without requiring a Node.js or TypeScript build on the production server.**

Start by auditing the existing project and reading the source documents. Then create the plan and begin implementation.
